## Common patterns to search & replace across files

- Repeated inline BoxDecoration / Padding / TextStyle objects — replace with shared constants or helper builders.
- Long `build()` methods — prefer composition: extract private StatelessWidgets inside the same folder/file or move to `presentation/widgets/<feature>/`.
- Inline business logic in screens (API calls, data transformations) — move to `riverpod` providers or `domain/use_cases`.
- Repeated string lists or long Markdown strings — move to assets or a `core/content` module.
- Synchronous waits / mock delays used in production screens — move to a test/helper or provider so screens only manage presentation.
